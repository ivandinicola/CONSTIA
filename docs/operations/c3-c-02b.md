## Arquitectura y decisiones trazables

1. Se usa un ejecutable independiente porque adquirir un lease en un contexto nuevo no demuestra terminar y reiniciar un proceso.
2. Se reutilizan las extensiones públicas de composición y el worker productivo. Un decorador de IOutboxBienvenidaRepository observa retornos ya durables; no cambia sus decisiones.
3. No hay hooks ni endpoints nuevos en producto. Control local exclusivamente por stdin/stdout y archivos privados del contenedor.
4. Se conserva la CI principal: los proyectos nuevos no se agregan a la solución, evitando que el filtro histórico ejecute SQL nuevo accidentalmente.
5. El escenario HTTP usa TestServer en memoria. Las variables sintéticas de ese host se restauran al cerrarlo; nunca se ejecuta en B2-A.
6. Cada usuario sintético se inserta pendiente y se guarda. La transición a verificado y el evento se guardan luego en una transacción. No se deshabilitan triggers.
7. Q13 y Q14 necesitan columnas sensibles en predicados. Conceder SELECT directo al observador incumpliría su restricción. Se crean en la base efímera módulos fijos de solo consulta con EXECUTE AS OWNER y parámetros tipados. El observador solo ejecuta esos módulos y no obtiene SQL arbitrario ni acceso directo a las columnas. No es un cambio ni una autorización de despliegue productivo.
8. Los planes se obtienen en otra sesión del migrador, con SHOWPLAN_XML y restauración en la misma conexión. La excepción primaria se preserva si falla la restauración; la conexión no usa pooling.
9. No se copian appsettings, secretos ni archivos locales al contexto de imagen. La composición parte de configuración explícita sintética.
10. Las pruebas utilizan temporizadores solo para observar señales/fechas durables. No introducen sleeps para ganar carreras. Los leases se esperan con reloj SQL real: no se finge que TimeProvider cambia SYSUTCDATETIME.
