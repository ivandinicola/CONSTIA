## Funciones incluidas

- Registro con elección explícita de zona IANA, confirmación de correo, login y logout. Mi cuenta permite cambiar la zona con la misma sesión, sin reescribir fechas civiles ni vigencias históricas. Los recursos pertenecen al usuario autenticado.
- Mis hábitos activos e inactivos, asistente de creación, edición con valores precargados y desactivación confirmada. Al menos un día semanal; `FechaInicio` asignada por el backend; categoría e ícono independientes. ETag/If-Match evita sobrescribir una edición obsoleta y el borrador se conserva para revisión explícita.
- Diez categorías y **28 íconos oficiales**, con los 16 IDs originales y su orden preservados y 12 incorporaciones aprobadas, incluidas Cuidado personal v3 y Caminata v2. Los legados conservan categoría/ícono nulos sin inferencias. La ampliación reutiliza IconoId, sin migración adicional.
- Hoy usa la fecha civil de la zona persistida vigente. Permite registrar un cumplimiento con botón nativo accesible, confirmación de resultado y reconciliación de incertidumbre. La API admite hoy/ayer locales y garantiza unicidad por hábito/fecha.
- Calendario mensual lunes–domingo, conteos y detalle diario de consulta. Días sin oportunidades neutrales, futuro como planificación y selección textual además de color. Rangos inclusivos de hasta 42 días, con lecturas en bloque.
- Historial por hábito activo o inactivo, con oportunidad y registro persistido separados; conserva registros fuera de programación o en fechas desconocidas. Acceso desde tarjetas expandidas y retorno con foco. No selecciona fechas futuras ni registra cumplimientos.
- Racha actual y mejor, generales e individuales. Umbral general `ceil(7 × programados / 10)`, días sin oportunidades neutros e individual por oportunidades históricas. La mejor no se limita a 42 días. Ventana de hoy/ayer y disponibilidad parcial; «Inactivo» en la actual cuando no aplica.
- Progreso y estadísticas individuales de los últimos 30 días civiles, hoy incluido como «En curso». «X de Y» y porcentaje sobre oportunidades, al entero más cercano con mitades hacia arriba. Cero, sin oportunidades e historial insuficiente se distinguen; las métricas determinables permanecen visibles.
- Carga y reintento por sección, sesión vencida y mensajes específicos de historial sin inicializar en Historial/Estadísticas. Calendario conserva su mensaje combinado ante 503, sin atribuir una causa específica. Si los cortes de Rachas y período difieren, cada sección conserva su fecha; «Rachas al [fecha]» identifica la diferencia. Un período rezagado conserva «Hoy»/«En curso» en su última fecha hasta actualizarse.

## Instalación local y seguridad

Seguí [DEVELOPMENT](../../DEVELOPMENT.md): Windows/PowerShell 7, SDK .NET 10, Docker Engine 28 o posterior y Compose v2. Compose levanta SQL Server 2022 por digest, puerto solo en loopback, volumen identificado y comprobación autenticada SELECT 1. API y Web se arrancan por sus perfiles HTTPS, no mediante servicios Compose incluidos.

Aplicá las 14 migraciones de la base de referencia e inicializá TEMP-005 mediante capture/backfill/status antes de habilitar operaciones dependientes. El arranque de API no ejecuta ese backfill. En una base con datos previos, conservá el corte y snapshot originales y seguí el procedimiento específico de la guía. La configuración y los secretos se cargan localmente, fuera de Git y de los logs.

Infrastructure fija Pkcs 9.0.21, propagado a seis consumidores; EF 10.0.12, SqlClient 6.1.6 y SNI 6.0.2 permanecen. Auditoría transitiva certificada sin paquetes vulnerables reportados ni supresiones. Las herramientas publicadas cargan 9.0.21. Esto no acredita por sí solo el framework compartido usado por API.

Para los avisos [454](https://github.com/dotnet/announcements/issues/454) y [468](https://github.com/dotnet/announcements/issues/468), la rama 10 debe estar corregida desde 10.0.13; la referencia local validada es .NET Runtime y ASP.NET Core Runtime Windows x64 **10.0.15**. El SDK no sustituye esa comprobación. API completa PID 15572 cargó Pkcs desde ASP.NET/10.0.15 con ruta, FileVersion, InformationalVersion y hash registrados mediante carga explícita de diagnóstico. No demuestra uso CMS por el negocio ni remediación externa. Instrumentación y recursos temporales retirados; SDK y Desktop conservados.

## Compatibilidad y operación

1. En un despliegue gradual, actualizar **todas las instancias Web a la versión compatible de PR #44 o posterior** antes de ampliar API a 28; comprobar sus revisiones en destino.
2. Web compatible acepta catálogos completos de 16 y 28 y muestra solo opciones disponibles/renderizables. Ante un 400 de iconoId en un alta abierta, recarga las opciones, conserva el borrador y exige una nueva acción para enviar.
3. Para revertir la ampliación, volver primero a API16 manteniendo Web compatible. Si existen IDs nuevos guardados, conservar esa Web para mostrarlos y preservarlos al editar otros campos. Web anterior + API28 queda fuera del orden admitido. Una reversión temporal a 16 no cumple el requisito de 28 de v0.1.0.

El alcance es **una sola instancia Web**: sesiones y coordinación de operaciones se conservan en memoria y los reinicios invalidan sesiones. Los borradores de alta se retienen hasta ocho por sesión y por una hora o hasta el vencimiento de la sesión. Recarga de un borrador confirmado recupera su resultado mientras siga retenido; resultados inciertos no causan reenvíos automáticos. La API no tiene idempotencia durable de creación. Tras una incertidumbre o reinicio, revisar Mis hábitos antes de crear otro borrador. Réplicas y recuperación durable requieren almacenamiento, claves/coordinación compartidos y un contrato específico; no están acreditados.

## Adaptaciones aprobadas y funciones diferidas

Se usaron recursos oficiales y se conservaron los diseños aprobados como referencia. Botones nativos reemplazan los deslizadores/gestos de autenticación y cumplimiento para permitir teclado; Calendario se entrega con conteos y consulta de lectura, sin puntos por categoría ni acciones de registro. Los selectores se ampliaron después del diseño estático original. No se afirma coincidencia visual exacta con todos los frames; entre las diferencias documentadas está la posición del aro de carga de Historial respecto de PEN-008. Algunos estados de Nuevo hábito se cotejaron solo contra su ficha escrita.

No incluye reactivación, proveedores sociales, recuperación/reenvío desde la interfaz, categorías personalizadas, recordatorios, estadísticas avanzadas ni aplicación móvil nativa. El selector IANA requiere `Intl.supportedValuesOf("timeZone")`; si falta, se muestra el aviso y no se permite completar el alta.

## Validación disponible y límites

La [matriz de aceptación](v0.1.0-aceptacion.md) enlaza implementación, PR, pruebas y custodia de evidencias. Las cifras corresponden a ejecuciones locales distintas, separadas de la CI del SHA:

- Catálogo: 695 unitarias, 141 Web, 86 HTTP focalizadas y una SQL aprobadas en Linux por bloqueo de DLL HTTP en Windows. HTTPS con Web/API/SQL reales acreditó 28 opciones, alta Estiramientos, edición/reapertura Caminata, relectura independiente y conservación de Billete/null.
- Cuenta/zona: 15 HTTP, 141 Web y tres SQL, además del salto de fecha con la misma sesión y conservación de fechas históricas.
- Pkcs: compilaciones, 10 HTTP, siete SQL y 53 pruebas de herramienta aprobadas, con una omisión preexistente documentada; CRUD con ambas herramientas publicadas.
- Arranque limpio PR #45: checkout y volumen nuevos, 14 migraciones y TEMP-005, HTTPS y 16 íconos en la API real de entonces. Ensayos reales posteriores acreditaron el catálogo de 28 y el runtime corregido.
- Ensayo final de runtime: Web/API/SQL reales, autenticación y rechazos, alta/edición, cumplimiento 201, duplicado 409 y relectura SQL independiente; seis intentos documentados y limpieza propia verificada. Se usó una cuenta sintética verificada sin enviar correo real.
- Las pruebas de pantalla/retorno de foco por entrega incluyen Chromium HTTPS con API sintética. Teclado, foco y anchos 280/320/390 se comprobaron en emulación; no acreditan dispositivos físicos, Safari real ni lectores de pantalla. Las evidencias visuales no sustituyen los recorridos reales y viceversa.

Quedan por verificar un futuro entorno desplegado, sus instancias, el runtime efectivamente seleccionado y el flujo de registro/recepción/confirmación de correo allí. El cierre local no declara disponibilidad pública. API-003 y API-005 permanecen abiertas para manejo global de errores y Swagger; no se incorporan como requisitos nuevos para etiquetar esta versión de código.
